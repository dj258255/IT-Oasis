*결제 시스템 시리즈 21편. 18편에서 만든 잣대가 천장에 닿았고, 그걸 뚫은 이야기다.*

## "구독으로 쓰면 안 되나"

상담 초안 이야기를 하다가 이런 요청을 받았다.

> 나 구독하고 있으니까 그걸로 쓰게 해도 괜찮아. 어차피 로컬에서 잠깐 테스트하는 건데.

**앱이 구독 자격증명으로 모델을 부르는 건 정책 이전에 기술적으로 안 된다.** CLI가 쓰는 건 API 키가 아니라 OAuth 토큰이고, 어댑터가 부르는 Messages API는 `x-api-key`를 받는다. 로컬이든 아니든 **인증이 성립하지 않는다.**

**그런데 목적은 이룰 수 있다.** 알고 싶은 건 "더 좋은 모델이 어떤 초안을 쓰는가"이고, 그걸 보는 데 **앱이 직접 호출할 필요는 없다.**

```
GET  .../cs-draft/prompt      ← 프롬프트를 그대로 꺼낸다
POST .../cs-draft/imported    ← 받아온 초안을 되돌린다
```

되돌리면 **같은 검사**를 태운다 — 숫자 검증, 용어 사전, 루브릭, 켜져 있으면 다른 계열 심판까지.

**같은 잣대를 태우는 게 요점이다.** 안 그러면 "저 모델이 더 잘 쓰더라"가 인상으로만 남는다. 이 프로젝트에서 인상이 틀린 적이 여러 번 있었다.

## 그래서 비교했더니 — 둘 다 만점

같은 4건에 대해 8B 초안과 프런티어 모델 초안을 나란히 채점했다.

| 케이스 | qwen3:8b | 프런티어 |
|---|---:|---:|
| 기록 없음 · 파일 지연 · 원인 불명 ×2 | **6/6** | **6/6** |

**잣대가 둘을 구분하지 못한다.**

### 그런데 읽어보면 같지 않다

루브릭이 못 보는 걸 따로 세어봤다.

| | qwen3:8b | 프런티어 |
|---|---:|---:|
| **안심 문구** ("추가로 청구되지 않는다") | **0 / 4** | **3 / 4** |
| 내부 정보 노출 (정산 확정일 등) | 1 / 4 | **0 / 4** |

구체적으로는 이렇다.

> **파일 지연 — 8B**: "…확인 중이며, **정산 확정일은 2026-08-30입니다**."
> 고객에게 의미 없는 내부 일정이다.
>
> **원인 불명 — 8B**: "…원인을 확인 중입니다. 결과가 확인되면 안내드리겠습니다."
> **추가 청구 여부를 말하지 않는다.** 고객이 가장 궁금해하는 게 그건데.

## 왜 못 잡나 — 내가 그렇게 만들었다

앞 편(18편)에서 이런 일이 있었다. 루브릭이 "고객 영향을 말하라"고 **요구했더니**, 모델이 점수를 채우려고 **알 수 없는 것까지 단언**했다.

> 차액 8,888원의 **원인을 확인 중**입니다. … **청구 금액은 그대로 유지됩니다.**

원인을 모르는데 결과를 장담한다. 그래서 **"원인이 확정된 건에만" 요구하도록** 바꿨다.

그 결정은 여전히 맞다. **부작용이 이거다.**

- "모르니까 아무 말도 안 한다" → 통과
- "모르지만 추가 청구는 없다고 약속한다" → 통과

**둘 다 통과한다. 뒤엣것이 분명히 나은데도.**

### 문제의 구조

여기서 문제가 뭔지가 선명해졌다.

> **필수로 걸면 모델이 지어내고, 안 걸면 잣대가 눈이 먼다.**

두 극단만 있었던 거다. 필수 아니면 없음.

## 답 — 가점

**요구하지 않으면서 재면 된다.**

- 통과 여부를 **안 바꾼다** — 가점이 없어도 6/6이다
- **프롬프트에도 안 넣는다** — 넣는 순간 그게 압력이 된다
- 비교할 때만 `필수 + 가점`을 쓴다

```java
/** 비교용 점수. 같은 만점끼리 <b>가르는</b> 값이다. */
public int comparable() {
    return passed + bonus.size();
}
```

가점 두 개를 달았다. 둘 다 **실제로 차이가 관측된** 축이다.

| 가점 | 왜 |
|---|---|
| 불확실할 때 추가 청구 없음을 약속했다 | **약속과 주장은 다르다** |
| 상관없는 내부 일정을 넣지 않았다 | 정산 확정일은 고객에게 의미 없다 |

### 약속과 주장의 구분

이게 이번 편에서 제일 마음에 드는 부분이다.

- **"이미 청구된 것이 멀쩡하다"** → 확인되지 않은 **주장**. 원인을 모르면 할 수 없다
- **"앞으로 추가로 청구하지 않겠다"** → 우리가 지킬 수 있는 **약속**. 원인을 몰라도 할 수 있다

루브릭은 **앞엣것을 막고**(필수 항목), 가점은 **뒤엣것을 권한다.** 같은 "고객 영향"인데 성격이 다르니 다르게 다뤄야 했다.

## 결과 — 구분된다

| | 필수 | 가점 | 합계 |
|---|---:|---:|---:|
| qwen3:8b | 24 / 24 | **4** | **28** |
| 프런티어 | 24 / 24 | **6** | **30** |

원인 불명 2건에서 갈렸다. 8B는 "결과가 나오는 대로 안내드리겠습니다"에서 멈추고, 프런티어 모델은 "확인이 끝날 때까지 **추가로 청구되는 금액은 없으며**"를 덧붙인다.

**필수 점수는 여전히 둘 다 만점이다.** 모델에게 점수 압력이 안 생기고, 그럼에도 비교는 가능해졌다.

그리고 **프롬프트에 안 넣었으니 8B가 못 받은 가점은 진짜 차이다.** 지시를 빼먹어서가 아니다.

## 남는 한계

**가점 항목도 결국 내가 골랐다.**

실험에서 관측된 차이를 축으로 만든 것이니, **그 두 축에서는 프런티어 모델이 이기게 되어 있다.** 새로운 차원의 차이는 여전히 못 본다.

그걸 넓히려면 사람이 초안을 읽고 "이건 왜 나은가"를 말해줘야 한다. 그게 블라인드 리뷰가 기다리는 자리고, 아직 표본이 없다.

## 남는 생각

이번 시리즈에서 같은 모양이 계속 나왔다.

**검사를 만들면 그 검사가 나를 속인다.** 무르면 나쁜 게 통과하고, 빡빡하면 좋은 게 떨어지고, 맞아도 검사 밖은 못 본다. 그리고 이번엔 하나 더 — **요구하는 순간 대상이 그 요구에 맞춰 변형된다.**

가점은 그 마지막 함정을 피하는 방법이었다. **재되 요구하지 않기.** 관찰자가 관찰 대상을 바꾸지 않게 하는 것에 가깝다.

그런데 이것도 완전하지 않다. **내가 고른 축만 본다.** 결국 어디까지 가도 "내가 안 본 것은 내가 못 잰다"로 돌아온다. 20편에서 밖에서 분류표를 가져온 것도, 다른 계열 모델을 심판으로 세운 것도 같은 문제를 다른 방향에서 친 거였다.

**혼자 만들면 시야가 만든 만큼이다.** 이 시리즈에서 제일 크게 배운 게 그거다.
