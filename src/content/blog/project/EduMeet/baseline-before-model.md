쌓인 자막을 검색하게 만들고 나서, **질문 형태에 약한 것**이 남았습니다.
*"락 얘기 어디서 했지"* 는 찾는데 *"왜 커넥션이 안 늘어나?"* 는 못 찾습니다.

의미 검색(임베딩)을 붙이면 되겠다고 생각했습니다.
그런데 붙이기 전에 **모델 없이 갈 수 있는 데까지 가 보기로** 했습니다.

---

## 다섯 방식을 같이 쟀습니다

질의 30개(용어형 15 / 질문형 15)로 쟀습니다. 아래는 **질문형 재현율**입니다.

| 방식 | 재현율 | |
|---|---:|---|
| 문자열 전체 매칭 | **0%** | 질의 전체를 부분문자열로 찾는다 |
| 토큰 매칭 | 43% | |
| **문자 2-gram** | **54%** | **모델 없음** |
| 임베딩 단독 | 60% | |
| 하이브리드(RRF) | **70%** | |

가장 큰 개선은 **임베딩이 아니라 문자열 매칭을 2-gram 으로 바꾼 것**이었습니다.

---

## 기준을 어디에 두느냐가 개선폭을 만듭니다

같은 모델인데 이렇게 적을 수 있습니다.

```
0%  → 70%     "의미 검색을 도입해 재현율을 70%p 올렸습니다"
54% → 70%     "의미 검색으로 16%p 더 얻었습니다"
```

**앞의 숫자는 모델의 기여가 아니라 비교 대상이 약해서 나온 값입니다.**

```
54%p  모델 밖에서 얻는다
16%p  venv 857MB 를 상주시켜야 얻는다
```

2코어 서버에서 857MB 를 상주시키는 값이 16%p 인지가 실제 질문이었습니다.
렉시컬을 기본으로 넣고 **임베딩은 선택 의존성**으로 뺐습니다. 기본값은 끄기입니다.

---

## 이득이 어디서 왔는지 분해하기 전까지는 그냥 숫자입니다

하이브리드가 2-gram 대비 개선한 5건을 **열어 봤습니다.**

```
락 ↔ 자물쇠      커넥션 ↔ 연결      트래픽 없을 때 ↔ 아무 말도 안 오가면
```

**전부 어휘 겹침이 0%** 였고, 오탈자나 띄어쓰기 변형은 **한 건도 없었습니다.**
즉 이 5건은 의미 이해 덕이 맞습니다.

이걸 안 열어 봤으면 *"임베딩이 16%p 올렸다"* 로 끝났을 겁니다.
그런데 **오탈자 보정으로 얻은 것이었다면 훨씬 싼 방법이 있습니다.**
숫자가 같아도 원인이 다르면 다음 선택이 달라집니다.

### 병합이 공짜가 아니라는 것도 나왔습니다

한 건에서는 하이브리드가 임베딩 단독보다 **낮았습니다**(67% → 33%).
순위 병합이 렉시컬 오답을 끌어올려 임베딩 정답을 밀어냈습니다.

가중치로 살릴 수 있지만 **질의 30개로 튜닝하면 그 30개에 과적합**이라 안 만졌습니다.
평균이 올랐다고 모든 질의가 나아지는 것은 아닙니다.

---

## 정리

**모델을 넣기 전에 베이스라인이 정당한지 봅니다.**

약한 베이스라인은 두 가지를 동시에 망칩니다 —
개선폭이 부풀려지고, **모델이 실제로 무엇을 해결했는지 모르게 됩니다.**

| | 안 하면 |
|---|---|
| 모델 없는 방법부터 다 잰다 | 모델이 한 일과 비교 대상이 약해서 생긴 차이를 못 가른다 |
| 개선된 건을 하나씩 열어 본다 | 같은 숫자가 나와도 다음에 무엇을 할지 못 정한다 |
| 평균만 보지 않는다 | 평균이 오르면서 어떤 질의는 나빠지는 것을 놓친다 |
