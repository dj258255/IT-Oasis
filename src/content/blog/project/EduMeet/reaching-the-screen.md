EduMeet의 존재 이유는 **실시간 자막**입니다. 청각장애 학습자가 수업을 따라갈 수 있게 하는 것.

백엔드에 자막 경로를 만들었습니다. 파이썬 AI가 넣으면 STOMP로 뿌리고, 지연을 세 개의
타임스탬프로 재는 것까지 했습니다.

**그런데 화면에 뜬 적이 한 번도 없었습니다.**

---

## 요약

- **문제**: 이 서비스의 존재 이유가 실시간 자막인데, **자막이 화면에 닿을 길이 없었습니다.** 백엔드는 STOMP 로 뿌리는데 프론트는 LiveKit 데이터채널만 듣고 있었습니다 — 참가자 브라우저끼리 주고받는 구조라 **서버가 만든 자막은 갈 곳이 없습니다.**
- **연결한 것**: 프론트 STOMP 클라이언트 · 하트비트 · 다시보기 패널 · 파이썬 전송 경로
- **조용한 종료를 만났습니다**: nginx 를 붙인 뒤 WebSocket 이 60초쯤에 끊기는데 **에러 로그가 한 줄도 안 남았습니다.**
    - 원인은 `proxy_read_timeout` 기본값 60초 — 프록시는 **읽을 것이 없는 연결**을 끊습니다
    - **→ 트래픽이 있으면 타이머가 계속 초기화되어 이 버그는 존재하지 않는 것처럼 보입니다. 부하를 주면 오히려 사라집니다**
- **그래서 시험을 반대로 설계했습니다**: 일부러 **아무것도 주고받지 않는 연결**을 만들어 얼마나 사는지 쟀습니다.
    - 기본값 60s — **60.9초에 3/3 종료** · 3600s — 90.1초에 **0/3**
- **두 겹으로 뒀습니다**: 프록시 타임아웃 + **STOMP 하트비트**. 프록시 설정은 인프라가 바뀌면 되돌아가지만 **하트비트는 앱이 들고 갑니다.**

## 1. 받는 쪽이 없었습니다

프론트를 열어 보니 자막을 이렇게 받고 있었습니다.

```js
currentRoom.on(RoomEvent.DataReceived, (payload, participant) => {
  if (data.type === 'caption') handleCaptionData(decoded);
  if (data.message && data.sender) { /* 채팅 */ }
});
```

**LiveKit 데이터채널입니다.** 참가자 브라우저끼리 직접 주고받는 구조라 **서버가 관여하지 않습니다.**

```
파이썬 AI   ❌ 자막 전송 코드 없음
백엔드      ✅ 내부 API → STOMP /topic/rooms/{id}/captions
프론트      ❌ STOMP 클라이언트 없음
```

세 군데 중 **두 군데가 끊겨 있었습니다.**

### 채팅도 같은 모양이었습니다

| | 프론트 | 백엔드 |
|---|---|---|
| 채팅 | LiveKit `publishData` | STOMP `/topic/rooms/{id}` |
| 자막 | LiveKit `publishData` | STOMP `.../captions` |

**두 벌인데 서로 만나지 않았습니다.**

그리고 LiveKit 데이터채널로는 **다시보기 채팅이 불가능합니다** — 서버를 안 거치니 저장할 수 없습니다.
앞 편에서 만든 배치 저장이 의미를 잃습니다.

---

## 2. 하트비트: 설정만 있고 안 나가는 것

프론트를 STOMP에 붙이면서 하트비트를 켰습니다. 채팅은 조용한 구간이 길어서
프록시가 유휴 연결로 보고 끊기 때문입니다(앞 편에서 60.9초에 끊기는 걸 쟀습니다).

```java
registry.enableSimpleBroker("/topic")
        .setHeartbeatValue(HEARTBEAT)
        .setTaskScheduler(heartbeatScheduler());   // ← 이게 없으면 조용히 꺼진다
```

**`setHeartbeatValue`만 주면 Spring이 하트비트를 조용히 끕니다.** 예외도 경고도 없습니다.
설정 파일만 보면 `25초`가 멀쩡히 적혀 있어서 켜진 줄 압니다.

이 저장소에서 반복된 패턴이라 **미리 테스트로 막았습니다.**

```
setTaskScheduler 제거   →  3개 실패
```

### 시험이 라이브러리를 쓰지 않는 이유

STOMP 클라이언트 라이브러리는 **하트비트 협상을 대신 처리하고 프레임을 감춥니다.**
우리가 보려는 것이 바로 그 프레임입니다. 원시 WebSocket으로 `CONNECTED`를 직접 읽습니다.

> 만드는 중에 한 번 막혔습니다. `CONNECT` 프레임을 **NUL로 끝내지 않아** 응답이 아예 안 왔습니다.
> 에러도 안 나고 *"연결은 됐는데 아무것도 안 온다"* 로만 보입니다.

### 그래서 프록시 타임아웃을 줄였습니다

앞 편에서 `proxy_read_timeout`을 3600초로 늘려 막았는데,
**그건 "죽은 연결도 한 시간 잡고 있겠다"는 뜻**이었습니다.

하트비트가 25초마다 나가니 **120초**면 됩니다 — 네 번 연속 놓쳐야 끊깁니다.

## 3. 마지막 빈 칸, 그리고 "실시간이 아니다"

파이썬에서 자막을 보내는 코드를 만들었습니다. 그런데 만들면서 알게 된 것이 있습니다.

```python
resp = requests.post(endpoint, files={"media": f}, timeout=600)
text = data.get("text")     # 전체 텍스트 한 덩어리
```

**CLOVA STT를 녹음이 끝난 뒤 파일 하나로 부릅니다.**
회의가 끝나야 텍스트가 나오는데 **실시간 자막을 만들 수는 없습니다.**

실시간으로 하려면 스트리밍 API로 바꿔야 하고, 그건 기능 추가입니다.

### 그래도 지금 잇는 이유

**소스를 바꾸는 순간 붙일 곳이 있어야 합니다.** 그리고 지금도 쓸 데가 있습니다 —
문장 단위로 보내면 **다시보기 자막**이 됩니다. 실시간은 아니지만 자막이긴 합니다.

### 숨기지 않습니다

```python
return {"ok": ..., "approximate_timing": True, "realtime": False, ...}
```

실제 발화 시각을 모르므로 균등 분배합니다.
**조용히 정확한 척하면 다시보기에서 자막이 어긋나도 원인을 못 찾습니다.**

## 4. 계약 구조가 실제로 막았습니다

앞 편에서 계약을 `contracts/internal-api.json`으로 옮기고 **양쪽 테스트가 같은 파일을 읽게** 했습니다.
이번에 그게 작동하는 걸 봤습니다.

| 되돌린 것 | 실패 |
|---|---|
| **계약 파일의 자막 경로 한 줄** | **Java 2개 + 파이썬 3개 동시** |

AI 연동이 오래 끊겨 있던 이유가 정확히 *"양쪽이 서로를 안 봤다"* 였는데, 이제 못 그럽니다.

## 5. 프론트에 테스트가 0개였습니다

```
backend   294개
ai         23개
frontend    0개   ← 러너조차 없었습니다
```

포트폴리오에 *"모든 수정을 회귀하면 깨지는 테스트로 고정했다"*고 써 놓고
**프론트에서 그 주장이 깨지고 있었습니다.**

vitest를 넣었습니다. 그런데 실행이 안 됐습니다.

```
TypeError: localStorage.getItem is not a function
  at getTimelineLayersStateFromStorage (@vue/devtools-kit)
```

### 그동안 Docker로 피하고 있던 것

`vite.config.js`가 `vue-devtools`를 **정적 import**하는데, 이 플러그인이
**모듈 로드 시점에 `localStorage`를 건드립니다.** Node 25의 `localStorage`는
객체로 존재하지만 `getItem`이 없습니다.

빌드는 Node 22 컨테이너로 돌려 피해 왔습니다. **하지만 테스트는 로컬에서 돌아야 의미가 있습니다.**

devtools는 개발 서버에서만 필요하므로 **동적 import**로 바꿨습니다.

> `command === 'serve'`만으로는 부족했습니다.
> **vitest가 내부적으로 vite 개발 서버를 띄워서** `command`가 `serve`로 옵니다.

이제 Node 25에서 빌드도 테스트도 됩니다.

## 6. 뗄 수 있는 것만 뗐습니다

`main.py`가 1,224줄이었습니다.

```
summarize_text_auto   471줄   테스트 0개
send_summary_to_api    94줄   계약 테스트 있음
send_captions_to_api   78줄   계약 테스트 있음
```

**테스트 없이 471줄 함수를 쪼개면 "동작이 바뀌었는지 알 방법이 없는 변경"이 됩니다.**
그런데 471줄이라 테스트를 쓸 수도 없습니다 — 닭-달걀입니다.

계약 테스트로 덮인 것만 `backend_client.py`로 분리하고, **나머지를 왜 안 뗐는지 적었습니다.**

> "정리했습니다"로 전부 옮기는 것보다, 뗄 수 있는 것만 떼고
> **못 뗀 이유를 적는 편이 정직합니다.**

### 분리 후에 확인한 것

**시험이 그대로 통과하는 것만으로는 부족합니다.**
시험은 `main`을 import하므로 **옛 코드를 그대로 보고 있을 수도 있습니다.**

```python
main.send_summary_to_api is backend_client.send_summary_to_api   # True
```

같은 객체인지 확인하고, `backend_client.py`를 고쳐서 시험이 깨지는 것까지 봤습니다.

## 배운 것

이 편의 작업은 전부 **"만들었는데 닿지 않는 것"을 잇는 일**이었습니다.

- 백엔드 자막 경로 → **받는 쪽이 없었습니다**
- 다시보기 조회 API → **부르는 곳이 없었습니다**
- 하트비트 설정 → **스케줄러가 없으면 안 나갑니다**
- 프론트 테스트 → **러너가 없었습니다**

만드는 것과 닿는 것은 다릅니다. 그리고 **닿지 않는 것은 조용합니다** —
에러가 안 나고, CI가 초록이고, 설정 파일에는 멀쩡히 적혀 있습니다.

그래서 이번에는 전부 **되돌려서 깨지는지** 확인했습니다.
깨지지 않으면 그 테스트는 아무것도 지키지 않는 것이니까요.

한 가지는 실제로 안 깨졌습니다. 다시보기 조회의 `IS NOT NULL` 조건인데,
**SQL 3값 논리 때문에 이미 범위 비교가 걸러내고 있었습니다.**
지우지 않고 *"지금은 중복이고 시험이 못 잡는다"*를 주석과 시험 양쪽에 적었습니다.
