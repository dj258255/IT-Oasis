강의 자막이 DB에 쌓이기 시작했습니다. 그런데 그것을 꺼내 보는 방법이 요약 파이프라인 하나뿐이었습니다.

에디터에서 *"지난주 강의에서 WebSocket 얘기 어디서 했지"* 라고 물어볼 수 있으면 좋겠다고 생각했습니다. MCP 서버를 붙였습니다.

```
MCP 클라이언트
    │ stdio
mcp-server ──── HTTP + X-Internal-Token ────► Java ────► caption_segment
```

## DB를 직접 읽지 않았습니다

파이썬에서 MySQL에 붙는 쪽이 빠릅니다. 의존성도 줄어듭니다. 그런데 자막을 꺼내는 SQL이 단순하지 않았습니다.

```java
ORDER BY
  CASE WHEN c.sequence IS NULL THEN 1 ELSE 0 END,
  c.sequence ASC, c.spokenAt ASC, c.id ASC
```

그리고 이 쿼리 위에 제가 직접 적어 둔 주석이 있었습니다.

> **여기서 순서가 흔들리면 요약 결과도 흔들린다.**

DB를 직접 읽으면 이 규칙을 파이썬에서 **한 번 더** 구현해야 합니다. 그리고 두 구현은 반드시 갈라집니다. 갈라져도 알 방법이 없다는 게 더 문제입니다 — 둘 다 "자막을 순서대로 준다"고 주장하고, 둘 다 자기 테스트가 통과합니다.

그래서 이미 있는 내부 API를 경유하기로 했습니다. 결과적으로 계약 파일 하나를 **셋이 읽게** 됐습니다.

```
contracts/internal-api.json
   ├── backend/     노출한 경로가 계약과 같은가
   ├── ai/          부르는 경로가 계약과 같은가
   └── mcp-server/  도구가 부르는 경로가 계약과 같은가
```

자바 쪽 계약 테스트는 **양방향**입니다.

```java
assertThat(actualInternal)
    .as("계약에 없는 내부 엔드포인트가 있다")
    .isSubsetOf(declared);
```

이번에 회의 목록 엔드포인트를 하나 추가했는데, 계약 파일을 안 고치니 이 테스트가 먼저 막았습니다. **계약을 적지 않고 엔드포인트만 늘리는 길이 없습니다.**

## ★ 그리고 조용히 틀리는 것을 찾았습니다

도구를 붙이고 `python`으로 검색해 봤습니다. **0건**이 나왔습니다.

오류가 아니었습니다. 그래서 더 나빴습니다.

```
STT   "python 을 배웠습니다"
        │  hot path 용어 사전
        ▼
저장   "파이썬 을 배웠습니다"
```

자막은 저장되기 전에 정규화를 지납니다. `python`은 `파이썬`이 되어 들어갑니다. 그래서 `python`으로 찾으면 걸리는 게 없고, 빈 결과는 이렇게 읽힙니다.

> *"이 회의에서 파이썬 얘기를 안 했나 보다."*

도구가 틀렸다는 신호가 **어디에도 없습니다.**

원인은 단순합니다. **정규화를 저장 쪽에만 걸어 뒀습니다.** 쓰는 쪽만 있을 때는 맞는 판단이었습니다. 읽는 쪽이 생기면서 비대칭이 드러난 겁니다.

## 사전을 어디에 둘 것인가 — 배포 형태가 정했습니다

고칠 방법은 명확했습니다. 질의에도 같은 사전을 적용하면 됩니다. 문제는 **그 사전을 어디에 두느냐**였습니다.

| | 판단 |
|---|---|
| MCP 쪽에 사전을 복사 | **기각.** 두 벌이 되면 한쪽만 고쳐도 시험이 통과합니다 |
| 공유 계약 파일을 하나 더 만들기 | **기각.** `ai/`는 도커 빌드 컨텍스트가 `./ai`라 `contracts/`를 런타임에 못 읽습니다 |
| `ai/caption_normalizer.py`를 그대로 import | **채택** |

두 번째를 기각한 이유를 조금 더 적습니다. 빌드 컨텍스트를 저장소 루트로 바꾸면 프론트와 ai의 수백 MB가 도커 데몬으로 전송됩니다. 그건 이 프로젝트가 이미 한 번 거부한 선택입니다.

세 번째가 가능한 이유는 한 가지입니다.

> **MCP stdio 서버는 컨테이너가 아닙니다.**

MCP 클라이언트 옆에서, 저장소 체크아웃 위에서 돕니다. 배포 단위가 없으니 빌드 컨텍스트 문제도 없습니다. 그냥 옆 디렉터리의 모듈을 import하면 원본이 하나로 유지됩니다.

**같은 문제라도 `ai/`였다면 이 답을 못 골랐습니다.** 배포 형태가 설계를 정한 경우입니다.

## 원문도 같이 찾습니다

정규화형만 쓰면 반대 방향으로 놓칩니다. 사전이 못 바꾼 영어 표기가 자막에 남아 있으면 그건 안 걸립니다. 그래서 둘 다 씁니다.

그리고 **빈 결과에도 무엇으로 찾았는지 적습니다.**

```
'쿠버네티스' — 찾은 말: 쿠버네티스 / 전체 42조각

걸린 조각이 없다.
```

사전이 질의를 바꿨는데 그 사실을 안 알려 주면, 0건이 다시 "안 했다"로 읽힙니다.

## 도구를 셋으로 나눈 이유

| | |
|---|---|
| `list_caption_meetings` | 고른다 |
| `search_transcript` | 찾는다 — 조각 단위 + 앞뒤 문맥 |
| `get_transcript` | 통째로 읽는다 |

`get_transcript` 하나만 두면 모델이 자막 전체를 컨텍스트에 넣습니다. 한 시간짜리 강의면 그것만으로 예산이 끝납니다.

문맥은 **글자 수가 아니라 조각 수**로 자릅니다. transcript의 한 줄이 자막 조각 하나이기 때문입니다. 줄 번호가 곧 조각 번호이고, 앞뒤 줄이 곧 앞뒤 발화입니다.

## 도구가 실제로 등록되었는지 묻습니다

이 저장소에서 같은 모양의 버그를 일곱 번 만났습니다. 요약하면 이렇습니다.

> **부품은 맞다. 그런데 연결되어 있는지는 아무도 안 물었다.**

MCP 도구도 같은 모양입니다. 함수가 옳게 동작해도 `@server.tool()`이 안 붙어 있으면 클라이언트에는 **아무것도 안 보입니다.** 그래서 함수를 부르는 시험과 별개로 서버에 직접 물어봅니다.

```python
def test_tools_are_actually_registered():
    names = {t.name for t in asyncio.run(server.list_tools())}
    assert EXPECTED_TOOLS <= names
```

실패도 잽니다. 도구가 예외를 던지면 클라이언트에는 "도구 실패"로만 보입니다. 설정 실수는 대부분 **서버가 아니라 MCP 클라이언트 설정**에 있으므로, 이유가 사람에게 문장으로 가야 합니다.

```python
assert out.startswith("실패:")
assert "EDUMEET_API_BASE_URL" in out
```

## 걸린 것 하나

MCP 파이썬 SDK가 2.0에서 `FastMCP`를 `MCPServer`로 바꿨습니다.

```
ModuleNotFoundError: No module named 'mcp.server.fastmcp'.
This is mcp 2.x, where FastMCP was renamed to MCPServer ...
```

인터넷에 있는 예제는 대부분 1.x입니다. 그래서 `mcp>=2,<3`으로 메이저를 못 박았습니다.

## 안 한 것

| | 근거 |
|---|---|
| 임베딩·벡터 검색 | 자막은 조각 단위 텍스트고 질의는 대부분 용어입니다. 의미 검색이 필요하다는 근거가 아직 없습니다 |
| 회의 간 전문 검색 | 아직 회의 하나 안에서 못 찾은 적이 없습니다 |
| MCP 서버 컨테이너화 | 컨테이너로 만들면 **용어 사전 공유가 오히려 깨집니다** |
| 쓰기 도구 | 읽기만 노출합니다. 토큰 하나로 내부 API 전체가 열리니까요 |

---

이 작업에서 얻은 것은 도구 세 개가 아닙니다. **읽는 쪽을 만들어 보기 전까지는 쓰는 쪽의 비대칭이 안 보인다**는 것입니다.
