자막이 DB에 쌓이는데 꺼내 쓰는 경로가 요약 파이프라인 하나뿐이었습니다. 에디터에서 *"지난주 강의에서 WebSocket 얘기 어디서 했지"* 를 물을 수 있게 MCP stdio 서버를 붙였습니다.

붙이자마자 **오류가 아니라 0건**이 나왔고, 그걸 고치고 나니 이번엔 질문 형태에 약한 게 남았습니다. 임베딩을 붙이면 되겠다고 생각했는데, 문서에 제가 이렇게 적어 둔 것이 있었습니다.

> **임베딩·벡터 검색** — 자막은 조각 단위 텍스트고 질의는 대부분 용어다.
> **의미 검색이 필요하다는 근거가 아직 없다**

기각을 뒤집으려면 근거를 먼저 만들어야 합니다. **재고 나서 붙이기로 했습니다.**

## 요약

- **먼저 나온 문제**: 도구를 붙이고 `python` 으로 검색하니 **0건**입니다. 자막은 hot path 용어 사전을 지나 `python → 파이썬` 으로 **정규화된 뒤 저장**되기 때문입니다.
    - **오류가 아니라 빈 결과**라 *"그 회의에서 그 얘기를 안 했다"* 로 읽히고, 도구가 틀렸다는 신호가 어디에도 없습니다
    - **→ 정규화를 저장 쪽에만 걸어 뒀습니다. 쓰는 쪽만 있을 때는 맞는 판단이었고, 읽는 쪽이 생기면서 비대칭이 드러났습니다**
- **그다음 문제**: 자막 검색이 질문 형태에 약했습니다. 그런데 문서에 *"의미 검색이 필요하다는 근거가 아직 없다"* 고 **기각해 둔 것**이 있어 근거부터 만들어야 했습니다.
- **재려고 보니 비교 대상이 허수아비였습니다**: 기존 구현이 질의 **문자열 전체**를 부분문자열로 찾고 있었습니다.
    - `비관적 잠금` → 1건 · `비관적 잠금 어디서 설명했지` → **0건**
    - **→ 질문 형태는 무조건 0건인데 의미 때문이 아니라 구현 때문입니다. 여기에 모델을 붙여 "0% → 70%" 라고 적으면 측정이 아닙니다**
- **모델 없는 베이스라인을 둘 더 만들었습니다**: 질의 30개(용어형 15 / 질문형 15) · k=5
    - 문자열 전체 **0%** → 토큰 매칭 43% → **문자 2-gram 54%**(모델 없음) → 임베딩 단독 60% → **하이브리드 70%**
    - **→ 54%p 를 공짜로 얻고, 그다음 16%p 에 venv 857MB 를 냅니다. 렉시컬을 기본으로 넣고 임베딩은 선택적 의존성으로 뒀습니다**
- **라벨에 결론을 넣지 않으려고 규칙을 뺐습니다**: 처음엔 *"질문형에는 자막의 단어가 하나도 없어야 한다"* 를 넣었는데 검증기가 제 질의 15개 중 13개를 걸렀습니다.
    - **→ 그건 결론을 미리 정해 놓는 것입니다.** 대신 어휘 겹침을 같이 보고했습니다(용어형 93% / 질문형 17%)
- **한 번도 안 도는 코드를 측정이 잡았습니다**: 의미 검색을 *"렉시컬이 0건일 때"* 로 짰는데, 2-gram 은 겹치는 조각이 하나만 있어도 결과를 내므로 **그 조건이 성립하지 않습니다.** 켜고 쟀는데 숫자가 꺼진 것과 똑같아서 알았습니다.
- **나중에 원인을 분해했습니다**: 2-gram 대비 **개선 5 · 회귀 0 · 동일 25** 이고 개선된 5건이 **전부 어휘 겹침 0%** 라 의미 이해 덕이 맞습니다. 다만 한 건은 **하이브리드가 임베딩 단독보다 낮았습니다**(67% → 33%). RRF 가 렉시컬 오답을 끌어올린 탓입니다

## DB를 직접 읽지 않았습니다

파이썬에서 MySQL에 붙는 쪽이 빠르고 의존성도 줄어듭니다. 그런데 자막을 꺼내는 SQL이 단순하지 않았습니다.

```java
ORDER BY
  CASE WHEN c.sequence IS NULL THEN 1 ELSE 0 END,
  c.sequence ASC, c.spokenAt ASC, c.id ASC
```

이 쿼리 위에 제가 직접 적어 둔 주석이 있었습니다.

> **여기서 순서가 흔들리면 요약 결과도 흔들린다.**

DB를 직접 읽으면 이 규칙을 파이썬에서 **한 번 더** 구현해야 합니다. 두 구현은 반드시 갈라지는데, **갈라져도 알 방법이 없다는 게 더 문제**입니다. 둘 다 "자막을 순서대로 준다"고 주장하고, 둘 다 자기 테스트가 통과합니다.

그래서 이미 있는 내부 API를 경유했습니다. 결과적으로 계약 파일 하나를 **셋이 읽게** 됐습니다.

```
contracts/internal-api.json
   ├── backend/     노출한 경로가 계약과 같은가
   ├── ai/          부르는 경로가 계약과 같은가
   └── mcp-server/  도구가 부르는 경로가 계약과 같은가
```

자바 쪽 계약 테스트는 **양방향**입니다. 이번에 회의 목록 엔드포인트를 하나 추가했는데 계약 파일을 안 고치니 이 테스트가 먼저 막았습니다. **계약을 적지 않고 엔드포인트만 늘리는 길이 없습니다.**

```java
assertThat(actualInternal)
    .as("계약에 없는 내부 엔드포인트가 있다")
    .isSubsetOf(declared);
```

## ★ 붙이자마자 조용히 틀리는 것을 찾았습니다

도구를 붙이고 `python`으로 검색해 봤습니다. **0건**이 나왔습니다. 오류가 아니었습니다. 그래서 더 나빴습니다.

```
STT   "python 을 배웠습니다"
        │  hot path 용어 사전
        ▼
저장   "파이썬 을 배웠습니다"
```

자막은 저장되기 전에 정규화를 지납니다. `python`은 `파이썬`이 되어 들어갑니다. 그래서 `python`으로 찾으면 걸리는 게 없고, 빈 결과는 이렇게 읽힙니다.

> *"이 회의에서 파이썬 얘기를 안 했나 보다."*

도구가 틀렸다는 신호가 **어디에도 없습니다.** 원인은 단순합니다. **정규화를 저장 쪽에만 걸어 뒀습니다.** 쓰는 쪽만 있을 때는 맞는 판단이었고, 읽는 쪽이 생기면서 비대칭이 드러난 겁니다.

### 사전을 어디에 둘 것인가: 배포 형태가 정했습니다

고칠 방법은 명확했습니다. 질의에도 같은 사전을 적용하면 됩니다. 문제는 **그 사전을 어디에 두느냐**였습니다.

| | 판단 |
|---|---|
| MCP 쪽에 사전을 복사 | **기각.** 두 벌이 되면 한쪽만 고쳐도 시험이 통과합니다 |
| 공유 계약 파일을 하나 더 만들기 | **기각.** `ai/`는 도커 빌드 컨텍스트가 `./ai`라 `contracts/`를 런타임에 못 읽습니다 |
| `ai/caption_normalizer.py`를 그대로 import | **채택** |

두 번째를 기각한 이유를 조금 더 적습니다. 빌드 컨텍스트를 저장소 루트로 바꾸면 프론트와 ai의 수백 MB가 도커 데몬으로 전송됩니다. 그건 이 프로젝트가 이미 한 번 거부한 선택입니다.

세 번째가 가능한 이유는 한 가지입니다.

> **MCP stdio 서버는 컨테이너가 아닙니다.**

MCP 클라이언트 옆에서, 저장소 체크아웃 위에서 돕니다. 배포 단위가 없으니 빌드 컨텍스트 문제도 없습니다. 옆 디렉터리의 모듈을 그대로 import하면 원본이 하나로 유지됩니다. **같은 문제라도 `ai/`였다면 이 답을 못 골랐습니다.** 배포 형태가 설계를 정한 경우입니다.

정규화형만 쓰면 반대 방향으로 놓칩니다. 사전이 못 바꾼 영어 표기가 자막에 남아 있으면 그건 안 걸립니다. 그래서 **원문과 정규화형을 둘 다** 씁니다.

### 도구를 셋으로 나눈 이유

| | |
|---|---|
| `list_caption_meetings` | 고른다 |
| `search_transcript` | 찾는다. 조각 단위 + 앞뒤 문맥 |
| `get_transcript` | 통째로 읽는다 |

`get_transcript` 하나만 두면 모델이 자막 전체를 컨텍스트에 넣습니다. 한 시간짜리 강의면 그것만으로 예산이 끝납니다. 문맥은 **글자 수가 아니라 조각 수**로 자릅니다. transcript의 한 줄이 자막 조각 하나라, 줄 번호가 곧 조각 번호이고 앞뒤 줄이 곧 앞뒤 발화입니다.

### 도구가 실제로 등록되었는지 묻습니다

이 저장소에서 같은 모양의 버그를 반복해서 만났습니다. 요약하면 이렇습니다.

> **부품은 맞다. 그런데 연결되어 있는지는 아무도 안 물었다.**

MCP 도구도 같은 모양입니다. 함수가 옳게 동작해도 `@server.tool()`이 안 붙어 있으면 클라이언트에는 **아무것도 안 보입니다.** 그래서 함수를 부르는 시험과 별개로 서버에 직접 물어봅니다.

```python
def test_tools_are_actually_registered():
    names = {t.name for t in asyncio.run(server.list_tools())}
    assert EXPECTED_TOOLS <= names
```

실패도 잽니다. 설정 실수는 대부분 **서버가 아니라 MCP 클라이언트 설정**에 있으므로, 이유가 사람에게 문장으로 가야 합니다.

```python
assert out.startswith("실패:")
assert "EDUMEET_API_BASE_URL" in out
```

> 걸린 것이 하나 있습니다. MCP 파이썬 SDK가 2.0에서 `FastMCP`를 `MCPServer`로 바꿨습니다. 인터넷 예제는 대부분 1.x라 `mcp>=2,<3`으로 메이저를 못 박았습니다.

**읽는 쪽을 만들어 보기 전까지는 쓰는 쪽의 비대칭이 안 보입니다.** 여기까지가 0건을 고친 이야기고, 아래부터가 그다음에 남은 질문형 약점입니다.

## 재려고 보니 비교 대상이 허수아비였습니다

```
"비관적 잠금"                 →  1건
"비관적 잠금 어디서 설명했지"   →  0건
```

기존 구현이 질의 **문자열 전체**를 부분문자열로 찾고 있었습니다.

```python
hit = next((original for original, low in lowered_terms if low in line), None)
```

질문 형태는 무조건 0건입니다. **의미 때문이 아니라 구현 때문입니다.**

여기에 임베딩을 붙여 *"0% → 70%"*라고 적으면 그건 측정이 아닙니다. **토큰 단위로만 바꿔도 상당 부분이 해결될 수 있고, 그러면 모델을 넣을 이유가 없습니다.**

그래서 모델 없는 베이스라인을 둘 더 만들어 같이 쟀습니다.

## 질의 세트를 어떻게 만들었나

| | |
|---|---|
| 용어형 **15** | 강의에서 쓴 말 그대로. 어휘 겹침 평균 **93%** |
| 질문형 **15** | 사람이 실제로 묻는 방식. 어휘 겹침 평균 **17%** |

용어형을 안 넣으면 *"새 방식이 좋다"*가 공짜로 나옵니다.

### 라벨을 인위로 비틀지 않았습니다

처음엔 검증 함수를 하나 만들었습니다. *"질문형 질의에는 자막에 나오는 단어가 하나도 없어야 한다."*

돌려 보니 제가 쓴 질의 15개 중 13개가 걸렸습니다. 고치려다 멈췄습니다.

**그건 결론을 미리 정해 놓는 것입니다.** 그렇게 만들면 어떤 렉시컬 방식도 질 수밖에 없고, 임베딩이 이기는 것이 **측정이 아니라 설계의 결과**가 됩니다.

대신 **어휘 겹침을 같이 보고**하기로 했습니다. 겹침이 낮은데 렉시컬이 찾으면 우연이고, 높은데 임베딩만 찾으면 그건 이상합니다. **결론을 읽을 때 이 값을 같이 봐야 합니다.**

## 결과

조각 60개 · 질의 30개 · k=5

| 방식 | 전체 recall@5 | 질문형 | MRR | 0건 | 질의당 | 추가 비용 |
|---|---:|---:|---:|---:|---:|---|
| A 문자열 전체 (전) | 50% | **0%** | 0.50 | 15/30 | 0.03ms | — |
| B 토큰 매칭 | 72% | 43% | 0.72 | 8/30 | 0.03ms | 없음 |
| **B′ 문자 2-gram** | **77%** | **54%** | 0.77 | 5/30 | 0.06ms | **없음** |
| C 임베딩 단독 | 80% | 60% | 0.80 | 2/30 | 15.4ms | venv 857MB |
| **D 하이브리드** | **85%** | **70%** | 0.81 | **0/30** | 16.9ms | venv 857MB |

```
질문형 재현율   0%  →  54%      문자열 전체 → 문자 2-gram.  값이 공짜입니다
              54%  →  70%      + 로컬 임베딩.  질의 지연 250배, venv 857MB
```

**54%p를 공짜로 얻고, 그다음 16%p에 857MB를 냅니다.**

### 용어형에서는 임베딩이 렉시컬을 못 이깁니다

다섯 방식 모두 재현율 100%입니다. 그런데 MRR은 임베딩 단독이 **0.97**로 오히려 낮습니다. 정확히 일치하는 조각을 1등에 못 놓는 경우가 있습니다.

**렉시컬을 버리면 잘하던 것을 잃습니다.** 하이브리드가 필요한 이유입니다.

### 형태소 분석기가 아니라 2-gram을 쓴 이유

*"끊깁니다 / 끊김 / 끊어"*를 이으려면 활용을 알아야 합니다. 형태소 분석기를 넣으면 의존성이 하나 늘고 **그 모델의 품질이 검색 품질에 섞입니다.**

문자 2-gram은 사전 없이 그 일부를 흡수합니다. 값이 싸고 설명이 짧습니다.

## 이렇게 넣었습니다

```
① 질의 문자열 전체가 그대로 있는 조각        조각 순서로
② 없으면 문자 2-gram 유사도 순위
③ 의미 검색이 켜져 있으면 ②와 RRF 로 병합
```

용어로 찾을 때 사람은 **정확 일치**를 기대합니다. `Redis`를 넣었는데 비슷한 조각이 위에 오면 도구가 이상해 보입니다. 그래서 ①이 먼저이고, ①에서 끊기면 모델을 아예 안 부릅니다.

## ★ 의미 검색이 한 번도 안 돌고 있었습니다

처음에 계단식 폴백으로 짰습니다. `정확 → 2-gram → 의미`.

켜고 쟀는데 숫자가 **꺼진 것과 똑같이** 나왔습니다.

2-gram은 겹치는 조각이 하나만 있어도 결과를 냅니다. 그래서 *"렉시컬이 0건일 때"*라는 조건이 **성립하지 않습니다.** 세 번째 단계는 도달 불가 코드였습니다.

> 이 저장소가 반복해서 만난 **"선언은 있는데 아무도 안 쓴다"** 를 또 만들 뻔했습니다.
> 이번엔 **측정이 잡았습니다.**

그리고 측정에서 이긴 것은 폴백이 아니라 **두 순위를 합치는 것**이었습니다.

### 점수를 더하지 않고 순위만 씁니다

코사인 0.83과 2-gram 0.21을 더하면 **척도가 큰 쪽이 항상 이깁니다.** 두 값은 단위가 다릅니다. 순위는 단위가 없고, 그래서 RRF입니다.

## 임베딩은 선택적 의존성입니다

```bash
pip install -r requirements.txt            # 렉시컬만.  질문형 54%
pip install -r requirements-semantic.txt   # + torch.  질문형 70%
export EDUMEET_SEMANTIC_SEARCH=1           # 설치만으로는 안 켜집니다
```

**설치돼 있다는 이유만으로 켜지 않습니다.** 켜면 모든 질의에 15ms가 붙는데, 용어로만 찾는 사용자에게 그 비용을 물릴 이유가 없습니다.

| | |
|---|---|
| 모델 | `intfloat/multilingual-e5-small` · 384차원 · 118M |
| 색인 | 조각 60개 **0.32초** / **0.09MB** |
| venv | 약 60MB → **857MB** |

**유료 키가 필요 없습니다.** 이 프로젝트가 AI 서비스를 못 띄우던 이유 세 개 중 하나가 사라졌습니다.

### 꺼져 있다는 것을 사용자에게 말합니다

질문형에서 못 찾았는데 이유를 안 알려 주면 *"그런 얘기를 안 했다"*로 읽힙니다. **용어 사전 때와 같은 실수입니다.**

```
※ 의미 검색이 꺼져 있다(EDUMEET_SEMANTIC_SEARCH 가 꺼져 있다).
   질문 형태로 물었다면 강의에서 쓸 법한 말로 다시 찾아본다.
```

## 나중에 지적받은 것: "+16%p가 의미 이해 덕"의 근거

임베딩을 붙여 질문형 재현율이 54% → 70%가 됐다고 썼습니다. 질문은 이거였습니다.

> **"그 16%p가 정말 의미 이해 덕인가요, 아니면 2-gram이 못 잡는 오탈자·띄어쓰기 변형을 임베딩이 우연히 커버한 건가요?"**

recall 집계만 있었고 **실패 원인 분해가 없었습니다.** 질의 30개를 하나씩 열었습니다.

```
2-gram 대비   개선 5 · 회귀 0 · 동일 25
```

개선된 5건이 **전부 어휘 겹침 0%** 였습니다.

| 질의 | 정답 조각의 표현 |
|---|---|
| 락을 걸어서 순서를 보장하는 방법 | "자물쇠를 거는 겁니다 / 비관적 잠금" |
| 측정 환경 바뀌면 결과가 달라지나요 | "저장소 엔진에 따라 다릅니다 / 인메모리로 재면" |
| 커넥션을 유지하는 프로토콜 | "한 번 연결하면 계속 열려 있습니다" |
| 트래픽 없을 때 커넥션 끊김 | "아무 말도 안 오가면 프록시가 연결을 끊어" |
| 블로킹 연산이 이벤트 루프를 막는 문제 | "오래 걸리는 계산 / 한 줄로 도는 구조" |

**오탈자·띄어쓰기 변형은 한 건도 없었습니다.** 전부 *"같은 것을 다른 말로 물은"* 경우라, 답은 **의미 이해 덕이 맞습니다.**

다만 **병합이 공짜가 아니었습니다.**

| 질의 | 2-gram | 임베딩 단독 | 하이브리드 |
|---|---:|---:|---:|
| 블로킹 연산이 이벤트 루프를 막는 문제 | 0% | **67%** | **33%** |

RRF 병합이 **렉시컬의 오답을 상위로 끌어올려 임베딩의 정답 하나를 밀어냈습니다.** 전체로는 이득이고 회귀도 0건이지만, 이건 원인을 분해하지 않았으면 못 봤을 것입니다.

가중치를 조정하면 이 한 건은 살릴 수 있습니다. **안 했습니다.** 질의 30개로 가중치를 튜닝하면 그 30개에 과적합됩니다. 질의 세트를 늘리기 전까지는 안 만지는 게 맞다고 봤습니다.
