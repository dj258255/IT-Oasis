## 결론부터

1. **위임 자동화에서 제일 위험한 것은 거짓 성공입니다.** 실패는 에러로 눈에 띕니다. 거짓 성공은 다음 단계로 그냥 넘어갑니다.
2. **완료를 문자열로 감지하면 두 군데에서 잘못 잡힙니다.** 지시문이 그대로 찍힌 명령어 줄, 그리고 이전 실행이 남긴 스크롤백입니다. 둘 다 실제로 당했습니다.
3. **처음 고친 방법은 셋이었습니다.** 지시를 파일로 빼고, 표식에 매번 다른 번호를 붙이고, 줄바꿈이 풀린 버퍼를 읽습니다.
4. **결국 판정 근거를 화면 밖으로 옮겼습니다.** 코더가 마지막 순서로 결과 파일을 쓰게 하고, 그 파일이 생기는지만 봅니다. 화면은 계속 다시 그려지지만 파일은 있거나 없거나 둘 중 하나입니다.
5. **Codex는 Chat Completions 방식을 더 이상 받지 않습니다.** 커스텀 제공자를 붙이려면 Responses API를 말해야 합니다.
6. **엔드포인트가 실재하는지는 404와 402를 구분해서 확인했습니다.** 잔액이 없어도 경로가 있으면 402가 돌아옵니다.
7. **라우팅의 기준은 캐시 유지입니다.** 한 묶음이 끝날 때까지 같은 코더에게 보냅니다.
8. **검토기는 구현기와 다른 모델이어야 합니다.** 같은 모델은 자기 실수를 그대로 통과시킵니다.
9. **아직 실제 기능 하나를 이 파이프라인으로 끝까지 통과시키지는 못했습니다.** 아래 내용은 붙이고 시험한 데까지입니다.

## 무엇을 만들려 했나

역할을 나누고 싶었습니다. 방향을 잡고 설계하고 검토하는 자리에는 비싼 모델을 두고, 코드를 실제로 쓰는 자리에는 싼 모델을 두는 구조입니다.

```
[1] 설계      방향, 문서, 체크리스트, 묶음 분해
      ↓
[2] 구현      묶음 하나를 다른 에이전트에게 위임
      ↓
[3] 간단 검토 구현기와 다른 모델이 diff를 본다
      ↓
[4] 최종 검토 설계한 쪽이 테스트를 직접 돌리고 머지
```

터미널 창을 나눠 에이전트를 띄우고 상태를 읽는 일은 herdr가 해 줍니다. 창을 만들고, 그 창에서 에이전트를 시작하고, 지시를 보내고, 끝날 때까지 기다리는 명령이 전부 있습니다.

```bash
herdr pane split --current --direction right --cwd "$PWD"
herdr agent start coder --kind codex --pane w5:p8 -- --profile deepseek -s workspace-write
herdr agent prompt coder "<지시>" --wait --until idle --until done --until blocked
herdr agent read coder --source recent --lines 200
```

여기까지는 문서대로 하면 붙습니다. 문제는 그다음이었습니다.

## 붙이기 전에 걸린 것 둘

**Codex가 Chat Completions를 버렸습니다.** 인터넷에 도는 예시는 대부분 이렇게 시작합니다.

```toml
[model_providers.something]
wire_api = "chat"
```

지금은 이 설정이 거부됩니다. 소스를 열어 보니 문자열 상수로 박혀 있었습니다.

```
`wire_api = "chat"` is no longer supported.
How to fix: set `wire_api = "responses"` in your provider config.
```

그래서 붙이려는 제공자가 Responses API를 지원하는지부터 확인해야 했습니다. 문서를 믿기 전에 직접 찔러 봤습니다.

```bash
curl -s -o /dev/null -w '%{http_code}' -X POST https://api.deepseek.com/v1/definitely-not-real ...  # 404
curl -s -o /dev/null -w '%{http_code}' -X POST https://api.deepseek.com/v1/responses ...            # 402
```

없는 경로는 404를 돌려주고, `/v1/responses`는 402를 돌려줬습니다. 잔액이 없는 계정이었으니 402는 **결제 단계까지 갔다는 뜻**입니다. 경로가 실재한다는 증거로 충분했습니다. 인증이 틀렸다면 401이 나왔을 겁니다.

**두 번째는 프로필이었습니다.** 설정 파일 안에 `[profiles.이름]`을 넣었더니 이렇게 거부했습니다.

```
--profile `deepseek` cannot be used while config.toml contains legacy `[profiles.deepseek]` config;
move those settings into <name>.config.toml
```

프로필이 별도 파일로 옮겨진 버전이었습니다. 기본 설정은 건드리지 않고 프로필 파일만 추가하는 쪽이 오히려 깔끔해졌습니다. 기본으로 실행하면 원래 모델이 뜨고, 프로필을 붙일 때만 다른 모델로 갑니다.

## 완료 판정이 두 번 거짓으로 통과했습니다

herdr가 에이전트의 상태를 알려 주는 건 지원하는 종류에 한합니다. 지원 목록에 없는 도구는 상태를 못 읽습니다. 그래서 출력에 표식을 찍게 하고 그 문자열을 기다리기로 했습니다.

```bash
herdr pane run "$PANE" cmd -p "... 마지막에 DELEGATE-RESULT 아래에 보고해" ...
herdr pane wait-output "$PANE" --match 'DELEGATE-RESULT'
```

**즉시 통과했습니다.** 에이전트는 아직 아무것도 안 했는데 말입니다. 무엇을 매칭했는지 보니 이랬습니다.

```
matched_line: "cmd -p 아무 파일도 건드리지 말고, 마지막 줄에 'DELEGATE-RESULT ...' 라고만 출력해 ..."
```

셸에 찍힌 **자기 명령어 줄**을 읽은 것이었습니다. 지시문 안에 표식이 들어 있으니 당연한 결과입니다.

지시를 파일로 빼서 명령줄에서 표식을 없앴습니다. 그리고 다시 돌렸더니 **또 즉시 통과했습니다.** 이번에 매칭한 줄은 조금 전 실패했던 실행이 화면에 남겨 둔 것이었습니다. 터미널 버퍼는 지워지지 않으니, 고정된 문자열로 기다리면 **과거의 성공을 현재의 성공으로 읽습니다.**

같은 자리에서 버그를 하나 더 만났습니다.

```
error: too many arguments. Expected 1 argument but got 8.
```

창에 명령을 실행하는 기능이 인자를 따옴표 없이 셸에 넘깁니다. 긴 한국어 문장을 통째로 실으면 공백마다 쪼개져 여덟 개의 인자가 됩니다.

## 그래서 이렇게 고쳤습니다

먼저 세 가지를 같이 적용했습니다. 지시를 파일로 빼서 명령줄에서 표식을 없애고, 표식에 매번 다른 번호를 붙이고, 읽을 때는 줄바꿈이 풀린 버퍼를 썼습니다. 화면에 보이는 그대로를 읽으면 긴 줄이 중간에서 잘리고, 그 지점에 표식이 걸치면 또 못 찾습니다.

```bash
TOKEN="DELEGATE-RESULT-$(date +%s)"
herdr pane wait-output "$PANE" --match "$TOKEN" --source recent-unwrapped --timeout 1800000
```

이 셋을 넣고 나서야 실제 출력의 표식에서 멈췄습니다. 고친 뒤에 확인한 것이 중요합니다. **처음 두 번은 "통과"라고 찍혔지만 아무 일도 일어나지 않았습니다.**

## 결국 화면 읽기를 버렸습니다

여기까지 해 놓고 방식을 바꿨습니다. 에이전트를 창에 띄워 놓고 지시를 타이핑해 넣는 쪽이 낫다고 판단했기 때문입니다. 작업이 도는 걸 눈으로 볼 수 있고, 수정 왕복을 같은 대화에 이어 보낼 수 있습니다. 매번 새로 실행하면 그때마다 코드베이스를 처음부터 다시 읽습니다.

```bash
herdr pane run "$PANE" cmd -t --skip-onboarding --auto-accept
herdr pane send-text "$PANE" "<지시>"
herdr pane send-keys  "$PANE" Enter
```

그런데 대화형 화면은 내용이 계속 다시 그려집니다. 표식이 찍혔다가 다음 갱신에서 사라지기도 하고, 상자 문자와 섞여 잘리기도 합니다. **표식 번호를 고쳐도 판정의 근거가 여전히 화면이라는 게 문제였습니다.**

그래서 신호를 화면 밖으로 옮겼습니다. 코더에게 **마지막 순서로 결과 파일을 쓰게** 하고, 그 파일이 생기는지만 봅니다.

```bash
herdr pane send-text "$PANE" "... 마지막으로 .delegate/result-$TOKEN.md 에 바꾼 파일과 테스트 결과를 써라."
for i in $(seq 1 360); do
  [ -f ".delegate/result-$TOKEN.md" ] && break
  sleep 5
done
```

파일은 다시 그려지지 않습니다. 잘리지도 않습니다. 있거나 없거나 둘 중 하나입니다. 시험에서는 5초 만에 파일이 생겼고 내용도 맞았습니다.

바꾸면서 하나를 더 배웠습니다. 대화형으로 띄우면 **파일을 쓸 때마다 승인 창에서 멈춥니다.**

```
Do you want to create .delegate/result-....md?
❯ 1. Yes    2. Yes, allow all edits this session    3. No, ...
```

편집마다 사람이 눌러야 하면 위임하는 의미가 없어집니다. 그래서 편집 자동 승인으로 띄우고, 바꾼 것은 나중에 diff로 한꺼번에 검토합니다. 대신 **작업 브랜치 위에서만 돌립니다.** 승인을 미룬 만큼 되돌릴 수 있는 자리를 먼저 만들어 둡니다.

## 라우팅은 캐시를 지키는 문제였습니다

모델을 여러 개 붙이고 나면 어느 작업에 어느 모델을 줄지 정해야 합니다. 처음에는 성능과 가격으로 표를 그렸습니다. 그런데 실제로 비용을 좌우하는 건 프롬프트 캐시였습니다.

같은 작업의 2차 시도에서 코더를 바꾸면, 새 모델은 그 코드베이스를 처음부터 다시 읽습니다. 캐시가 살아 있던 쪽에 계속 주는 편이 쌉니다. 그래서 규칙을 이렇게 잡았습니다.

- 한 묶음이 끝날 때까지 코더와 창을 고정합니다.
- 코더 교체는 묶음 경계에서만 합니다.
- 묶음을 나눌 때 파일이 겹치지 않게 합니다. 겹치면 머지 충돌과 캐시 손실이 같이 옵니다.
- 읽어야 할 파일이 많아 27만 토큰을 넘길 것 같으면 컨텍스트가 큰 모델로 보냅니다.

여기에 현실적인 제약이 하나 더 붙습니다. **가진 코더마다 막히는 신호가 다릅니다.** 어떤 것은 `402 Insufficient Balance`로, 어떤 것은 사용 한도 안내와 재설정 시각으로, 어떤 것은 크레딧 소진 안내로 멈춥니다. 라우팅 규칙에 이 신호를 같이 적어 두지 않으면 막힌 코더에게 계속 보내다가 묶음 하나를 통째로 날립니다.

## 검토기는 구현기와 달라야 합니다

구현한 모델에게 자기 diff를 검토시키면 의미가 없습니다. 자기 출력을 스스로 평가할 때 생기는 편향은 알려져 있고, 실제로도 "테스트 통과"라고 적은 보고를 그대로 믿을 수 없습니다.

그래서 검토기를 구현기와 다른 계열로 두고, 막히면 내려가는 순서를 정했습니다. 원래 쓰려던 모델이 사용 한도에 걸려 있어서, 실제로는 세 번째 후보로 검토를 돌렸습니다. 후보를 하나만 적어 뒀다면 그날 검토는 통째로 건너뛰었을 겁니다.

검토를 통과해도 마지막에 한 번 더 확인합니다. 설계한 쪽이 diff를 직접 읽고, **완료 조건의 테스트를 직접 돌립니다.** 코더와 검토기가 둘 다 통과했다고 적어도 다시 돌립니다. 테스트를 지우거나 건너뛰게 고쳐서 통과시킨 흔적이 있는지도 그때 봅니다.

## 남은 것

아직 실제 기능 하나를 이 파이프라인으로 끝까지 통과시키지 못했습니다. 지금까지 확인한 것은 창을 나누고, 에이전트를 띄우고, 지시를 보내고, 완료를 감지하고, 결과를 읽는 데까지입니다. 진짜 작업을 태워 봐야 알 수 있는 것이 남아 있습니다. 묶음을 어느 크기로 잘라야 검토가 감당되는지, 2차 시도에서 캐시가 실제로 얼마나 아껴 주는지 같은 것들입니다.

자동화를 더 밀어붙일 수도 있습니다. 세션이 끝날 때 다음 묶음을 자동으로 시작하게 걸면 사람 없이 밤새 돕니다. 지금은 묶음마다 사람이 승인하게 두었습니다. 이유는 이 글의 첫 문장과 같습니다. **거짓 성공을 사람이 안 보면 그대로 머지됩니다.** 완료 표식 하나도 두 번이나 거짓으로 통과한 마당에, 그 판정을 무인으로 돌릴 자신은 아직 없습니다.
